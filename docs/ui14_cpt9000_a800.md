## 四步命令

依次运行。第二步在已分配四张 A800 的节点运行；第一、三步只使用 CPU。第四步在有 `mlx` 的集群提交环境运行。
默认使用 `${WORKSPACE}/conda_envs/LocateAnything/bin/python`。CPU 数据阶段只需要 Pillow、NumPy、SciPy、PyYAML、openpyxl，不初始化 CUDA。

```bash
cd /mnt/bn/intelligent-service-yg/logging/sicheng_workspace/code/Eagle_LocateUI5_v4/Embodied-ui14-cpt9000

# 1. CPU：读取落地 manifest 和固定 train/test，生成注册表、规范化标注。
bash shell/ui14_cpt9000_a800.sh normalize

# 2. GPU：只生成新增七个 crop 任务的 train/test detector、横向计划及 crop 标注。
bash shell/ui14_cpt9000_a800.sh cache

# 3. CPU：组装联合 recipe、14 项原图评测清单、完整 check 和正式 YAML。
bash shell/ui14_cpt9000_a800.sh finalize

# 4. 提交正式训练。内部使用 --machine a800 --resource-group aiai_locate --gpus 4。
bash shell/ui14_cpt9000_a800.sh submit
```

## 输入与输出

输入根目录：`/mnt/bn/intelligent-service-yg/dataset/gui/ui9_datasets_v1`。
读取其 `manifest.json` 和各任务 `${task_key}/{train,test}.jsonl`，不重新切分或复制原图。
manifest 的 `tasks` / `datasets` / `sources` 支持按 task_key 索引的对象或带 task_key 的列表；实际文件数量由落地 JSONL 读取，并核对 manifest 中提供的 `train_count/test_count` 或 `train_records/test_records`。

全部派生输出位于 `${WORKSPACE}/gui_data/ui14_cpt9000_v1`：

| 相对路径 | 内容 |
|---|---|
| `task_registry.json` | 固定 ID、来源、family、提示词、view_policy、train/test 路径 |
| `normalized/<task_key>/{train,test}.jsonl` | 九个新来源的 18 份原图像素标注；保留 source_metadata |
| `detector_inputs/<task_key>/{train,test}.jsonl` | 只含待检测截图路径，无 GT/参考图/原始提示词 |
| `cache/<task_key>/<split>/detections/` | 七个 crop 任务独立的 OCR/icon 原始 detector 结果 |
| `cache/<task_key>/<split>/horizontal_scan_v5_raw_detector_edge_aligned/` | 无 GT 裁剪计划、统计、gallery、摘要绑定 ready marker |
| `crop_images/<task_key>/<split>/` | 原图身份与 scan 编号命名的 PNG crop |
| `derived/<task_key>/{train,test}.jsonl` | 新九项派生 train/test；旧五项只派生 train，原测试文件直接复用 |
| `derived/<task_key>/{train,test}.coverage.json` | GT 完整落入 crop / 跨裁剪线的数量；不反向改变裁剪 |
| `evaluation_inputs/<task_key>.jsonl` | 新九项完整 test，按原图身份合并重复行的多框 GT |
| `training_recipe.json` | 14 路显式等权训练流，只引用 train |
| `evaluation_manifest.json` | 完整 14 项原图评测清单、各自缓存和 Figma 策略 |
| `normalization_stats.json`, `sampling_stats.json` | 来源记录数、原图数、标签比例、实际采样比例、人工修复保留量 |
| `image_overlap.json` | 包括 UI5 和跨来源的 train/test 原图内容重复明细 |
| `cpu_check_report.json` | 实际集群输入、坐标连接、缓存、采样、评测、checkpoint、YAML 检查 |
| `formal_job.yaml`, `formal_runtime.json` | 本次实际提交配置 |

原图身份使用解码 RGB 像素及尺寸的 SHA-256。不同路径、不同 PNG/JPEG 编码的相同像素会被识别为同一图。
冻结 split 中发现的重复如实报告，不删除或随机重分已有导出；所有 crop 继承原图 split。
重复来源仍是不同训练任务，标签、采样、缓存和评测独立。

## 任务与标注约定

统一注册表实现在 `eaglevl/ui_task_registry.py`。原 UI5 模型 ID 为 0 overflow、1 cropping、2 occlusion、3 ellipsis、4 missing；训练别名和旧评分 class_id 映射保持兼容。

| ID | task_key | view_policy | relation_family |
|---:|---|---|---|
| 0 | text_overflow | crops | boundary |
| 1 | cropping | crops | boundary |
| 2 | occlusion | crops | pairwise |
| 3 | text_ellipsis | crops | text |
| 4 | content_missing | full_image | presence |
| 5 | ui_alignment | full_image | pairwise |
| 6 | change_line_illegal_v3 | crops | text |
| 7 | synth_cropping | crops | boundary |
| 8 | synth_occlusion | crops | pairwise |
| 9 | synth_radius | crops | boundary |
| 10 | synth_loneword | crops | text |
| 11 | synth_large_margin | full_image | pairwise |
| 12 | synth_inner_margin | crops | boundary |
| 13 | synth_small_margin | crops | pairwise |

两个已有来源读取 `objects.bbox/bbox_type`；合成来源读取 `ScreenShotURL` 和 `Objects[].Location`（支持 Location 列表或对象）。每个 Location 的优先级为 `rect_err > rect_mbr > rect*_shift > rect_combine > rectN`，同优先级多框保留。

合成框先用 `s=W/375` 将 X/Y 四个坐标同时转换为原图像素，再减 crop 偏移，最后按当前输入宽高转 0–1000。`BBoxCanvasWidth` 声明非 375 会报错。正常框使用原有四舍五入；裁剪产生的小于一个归一化单位的片段向外量化一个单位，避免静默丢框。每个来源保存 source_dataset/source_version/source_record_id/source_image_id/split/task_key/crop_id。

训练问题全部由注册表生成 `Locate all the instances that match the following description: ...`，答案使用原 `<ref>...<box>...` / `<box>none</box>` 格式。原 messages 仅在原始来源资料中保存。正样本必须选择 ScreenShotURL；现有记录明确 `Objects=[]` 且没有 ScreenShotURL 时，允许其指定的参考图作为该条负样本输入；从不因参考图存在而生成新负样本。

旧审核 recipe 和旧完整 test detector cache 只读复用：

```text
/mnt/bn/intelligent-service-yg/logging/sicheng_workspace/code/Eagle_LocateUI5_v4/Embodied-ui5-det-crop/work_dirs/ui5_crop_audit_20260825/crop_audit_v4_gt_repair/training_recipes/ui_defect_5class_train_crop_only.json
/mnt/bn/intelligent-service-yg/logging/sicheng_workspace/code/Eagle_LocateUI5_v4/Embodied-ui5-det-crop/work_dirs/ui5_eval_detector_cache_horizontal_v5/horizontal_scan_v5_raw_detector_edge_aligned/detector_scan_crops.jsonl
```

UI5 保留审核 marker、排除清单及全部有效人工修复记录。新缓存沿用 PP-OCRv5 / OmniParser 的 detector 配置，OCR Python 从旧缓存 `detections/text/stage_summary.json` 读取，默认后备为 `conda_envs/UI5PaddleOCR/bin/python`；可用 `--text-python` 显式指定实际环境。

新七项仍使用 v5 原始 detector 边缘、严格横向分区和相同 DP。额外的 `ui14_detector_neighbors_v1` 只排除会拆开相近且横向重叠的 detector 关联组的候选线：文本保留相邻行，boundary/pairwise 保留邻近容器/元素。没有合适的原始边缘时按 v5 减少 crop 数至单张全宽 scan。该规则只读 detector，不读 GT；覆盖报告不会触发 GT repair、过滤测试数据或重排测试 crop。

## 正式训练、恢复与评测

初始化固定为 `${WORKSPACE}/gui_models/locany-3b-ui-cpt-v4-v3-h20x2-formal-segmented-eval/checkpoint-9000`。
BASE_MODEL=MODEL_PATH=INIT_CHECKPOINT，INIT_CPT_STEP=9000，LOCANY_CPT_MODE=0。新 SFT 从 optimizer step 0 开始，CPT 的 optimizer/scheduler 不恢复；恢复只使用新运行目录内的 SFT checkpoint。

输出：`${WORKSPACE}/gui_models/locany-m32-cpt9000-ui14-a800x4-v1`。
运行 profile 为 `configs/ui14_cpt9000_formal.json`：单节点 A800 40GB × 4，group_id=2146，`ies_aiai_experience/AIAI_locate`，队列 `compute-3302-yg-cloudnative-ai-aiai.locate-guarantee`；SDPA、BF16、ZeRO-2 two-lr、batch=1、GA=2、sequence/sample=7268、每 rank tokens=12800、16k optimizer steps、seed=42、warmup=500、cosine、LR=1e-5/relation LR=2e-5、weight_decay=.01、grad_norm=1。MoonViT attention、M32、PBD、observe gate 和其余损失沿用基线。

14 路默认采样权重各为 1。每路按源图均衡并轮换 crop；双侧任务 negative:positive=2:1，单侧任务只抽取实际存在侧，并记录实际比例。task-indexed embedding、expert、image gate 和输出头扩展至 14；relation family 保留 4。checkpoint config 和 processor 保存任务数量与完整注册表，patch 同步导出可独立加载的注册表模块。

每 100 optimizer steps 写训练窗口。底层保留每步 scalar 收集，以计算 100 步窗口；不是每 100 个 microbatch。
每 1000 SFT optimizer steps 分段退出训练，四张卡各一条独立评测 worker，完成任务继续领取，完整跑同一 checkpoint 的 14 项 test。评测只读预生成缓存。新九项不做 Figma 路径/文件名过滤；旧五项 no_figma 和 1555 原图口径保持原值。预测先映回原图合并，随后使用原 IoU=.1、Hungarian 匹配和非法输出惩罚。

评测结束恢复 optimizer、scheduler、RNG、数据进度，总 MAX_STEPS 仍是 16000，学习率不按分段重新 warmup。评测运行失败时保持当前 checkpoint，修复后执行同一提交命令补齐本轮，再继续训练；不以缺失 UI9 的 UI5 结果判定完成。

`${OUTPUT_DIR}/diagnostics/ui5_training_evaluation.xlsx` 保持两个 sheet：

- `train_100steps`：新增九项独立 loss、样本数、正负、gate、M32 诊断及任务来源/初始化信息。
- `eval_1000steps`：每轮 36 行，14 项 × image/bbox，加 five_task_macro/micro 和 ui9_macro/micro 各 image/bbox。bbox TN 留空；无负样本来源 negative_count=0。

每 4k 正式 checkpoint，以及每 1k 严格提升的旧 UI5 image/bbox macro F1 最佳 checkpoint，保留策略沿用基线。UI9 单独展示，不参与旧 best 字段。逐图预测、gate sidecar、evaluation_history、best_checkpoints 和 ui14-step 完整性状态均保留。
